Collection 集合

集合概述

集合是一种长度可变的容器，用来存储多个对象。与数组相比，集合的长度可以动态增长。

特点：

  • 长度可变
  • 只能存储引用类型（基本类型会自动装箱）
  • 提供大量方法操作元素

分类：

  • 单列集合：元素只有一部分，list.add("元素")
  • 双列集合：元素由 key 和 value 两部分构成（键值对）

Collection 接口

Collection 是单列集合的顶级接口。

常用方法：

方法 说明
boolean add(E e) 添加元素（add 一定成功，通常不用接收返回值）
boolean addAll(Collection<? extends E> c) 合并另一个集合
void clear() 清空所有元素
boolean contains(Object o) 判断是否包含指定元素
boolean isEmpty() 判断集合是否为空
boolean remove(Object o) 删除指定元素
int size() 返回元素个数
Object[] toArray() 转为数组

数据结构

1. 栈

先进后出（如同压子弹）。最后放进去的最先弹出来。

2. 队列

先进先出（如同排队）。最先排队的最先出来。

3. 数组

  • 查询快：有索引，可通过索引快速定位元素
  • 增删慢：定长，扩容需要新建数组并复制

4. 链表

  • 查询慢：需要从头依次遍历
  • 增删快：只需修改相邻节点的引用

单向链表：每个节点由数据域 + 指针域构成，每个节点只记录下一个节点的地址。

双向链表：每个节点由前驱指针 + 数据域 + 后继指针三部分构成，头尾节点互相记录地址。Java 中的 LinkedList 采用双向链表实现。

迭代器

Iterator 用于遍历集合。

方法说明：

方法 说明
boolean hasNext() 判断是否有下一个元素
E next() 获取下一个元素

并发修改异常：

在迭代过程中使用集合自身的 add / remove 方法修改集合长度，会触发 ConcurrentModificationException（并发修改异常）。

底层原理： ArrayList 迭代器底层是内部类 Itr，实现了 Iterator 接口。迭代器记录了集合的预期修改次数 expectedModCount，每次操作前会与实际修改次数 modCount 比较，不一致则抛异常。

List 接口

List 是有序的集合（有索引、可重复）。

实现类： ArrayList、LinkedList、Vector

ArrayList

特点： 有序、有索引、元素可重复、线程不安全、数据结构为数组。

底层扩容机制：

  • 无参构造：第一次 add 时才创建长度为 10 的数组，超出后扩容 1.5 倍（懒加载）
  • 有参构造：直接创建指定长度的数组，超出后扩容 1.5 倍

常用方法：

方法 说明
boolean add(E e) 尾部添加
void add(int index, E e) 指定索引插入
E remove(int index) 按索引删除（返回被删元素）
boolean remove(Object o) 按元素删除
E set(int index, E e) 修改指定索引元素
E get(int index) 获取指定索引元素
int size() 元素个数

⚠️ 注意：list.remove(2) 会调用按索引删除的方法；如果想删除元素 2（Integer），需要写成 list.remove(Integer.valueOf(2))。

LinkedList

特点： 有序、无索引、元素可重复、线程不安全、数据结构为双向链表。

特有方法（直接操作首尾）：

方法 说明
void addFirst(E e) 头部插入
void addLast(E e) 尾部插入
E getFirst() 获取头部元素
E getLast() 获取尾部元素
E removeFirst() 删除并返回头部
E removeLast() 删除并返回尾部
E pop() 弹出（相当于 removeFirst，常配合 push 模拟栈）
void push(E e) 压栈（相当于 addFirst）

底层原理： LinkedList 内部维护 Node<E> 节点，包含 item（数据）、prev（前驱）、next（后继）。get 方法采用二分思想：若 index < size/2 则从头遍历，否则从尾遍历，减少遍历次数。

Vector（了解）

特点： 有序、有索引、元素可重复、线程安全（synchronized）、数据结构为数组。

  • 无参构造直接创建长度为 10 的数组，超出后扩容 2 倍
  • 有参构造按指定增量扩容

一般不使用 Vector，除非需要线程安全（推荐使用 CopyOnWriteArrayList 或 Collections.synchronizedList）。

增强 for

增强 for（也称 for-each）是简化遍历的语法，底层原理遍历集合时就是迭代器。

快捷键： 集合名 .for

注意： 遍历集合时底层是迭代器，因此在增强 for 中不要修改集合长度，否则可能触发并发修改异常。

Set 接口

Set 是无序（不保证顺序）、无索引、元素不可重复的集合。

实现类： HashSet、LinkedHashSet、TreeSet

HashSet

特点： 无序、无索引、元素唯一、线程不安全、数据结构为哈希表。

  • JDK 7 及以前：哈希表 = 数组 + 链表
  • JDK 8 及以后：哈希表 = 数组 + 链表 + 红黑树（链表长度 ≥ 8 且数组容量 ≥ 64 时转化）

LinkedHashSet

特点： 有序（按插入顺序）、无索引、元素唯一、线程不安全、数据结构为哈希表 + 双向链表。

HashSet 的链表是单向的，无法记录顺序；LinkedHashSet 用双向链表维护插入顺序。

TreeSet

特点： 可对元素排序、无索引、元素唯一、线程不安全、数据结构为红黑树。

构造方法：

构造 说明
TreeSet() 按自然排序（ASCII 码）
TreeSet(Comparator<? super E> comparator) 按指定规则排序

哈希值

哈希值是 Java 根据对象内容计算出的十进制整数（可理解为”逻辑地址”）。

关键结论（需背下来）：

  • 哈希值不一样 → 内容一定不一样
  • 哈希值一样 → 内容有可能一样（哈希冲突 / 哈希碰撞）
  • 想让哈希值反映对象内容，需要重写 hashCode 方法（IDE 通常自动生成）

红黑树（了解）

红黑树是一种自平衡的二叉查找树，Java 中 TreeSet / TreeMap 底层使用它来保证元素的有序性和高效查找。

5 大性质：

  1. 每个节点非红即黑
  2. 根节点是黑色
  3. 叶节点（NIL）是黑色
  4. 红色节点的子节点必须是黑色（不能出现两个红色节点相连）
  5. 从任一节点到其所有后代叶节点的路径上，黑色节点数目相同

特点： 保证最长路径不超过最短路径的 2 倍，树大致平衡，查找效率稳定在 O(log n)。

可视化网站：https://www.cs.usfca.edu/~galles/visualization/RedBlack

各集合对比总结

集合 有序 有索引 元素唯一 线程安全 数据结构 扩容倍数
ArrayList ✅ ✅ ✅ 可重复 ❌ 数组 1.5倍（懒加载首次10）
LinkedList ✅ ❌ ✅ 可重复 ❌ 双向链表 无
Vector ✅ ✅ ✅ 可重复 ✅ 数组 2倍（首次10）
HashSet ❌ ❌ ✅ 唯一 ❌ 哈希表 2倍（首次16，加载因子0.75）
LinkedHashSet ✅ ❌ ✅ 唯一 ❌ 哈希表+双向链表 同 HashSet
TreeSet 排序 ❌ ✅ 唯一 ❌ 红黑树 无
