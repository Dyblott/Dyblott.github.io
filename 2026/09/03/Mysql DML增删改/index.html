MySQL 增删改（DML）

概述

DML（Data Manipulation Language） 是 SQL 中用来对表中的数据进行增、删、改的语言，对应的核心三个关键字：

关键字 作用
INSERT 插入（增）
UPDATE 修改（改）
DELETE 删除（删）

注意 DML 只动数据，不动表结构（表结构属于 DDL：CREATE / DROP / ALTER）。

一、INSERT（增）

1. 全字段插入

按表中字段的全部顺序依次插入，字段名可以省略。

2. 部分字段插入

只给部分字段赋值，未赋值的字段使用默认值（默认 NULL 或建表时指定的 default）。

3. 批量插入

用一条 INSERT 插入多行数据，比逐条插入效率高得多（日志、索引刷新只做一次）。

4. 蠕虫复制（表结构相同时）

把另一张表的数据整张复制过来，常用来构造压力测试数据。

5. INSERT 时的注意事项

注意点 说明
字段数量 值的数量必须与字段数量完全一致
字段顺序 给值的顺序必须与字段顺序一一对应
字符串 必须用单引号包起来：'张三'，MySQL 弱类型校验，双引号也能跑但不推荐
日期 同样用单引号：'2026-09-03'、'2026-09-03 16:13:00'
主键冲突 重复主键会报错：Duplicate entry '1' for key 'PRIMARY'

注意点 说明
⚠️ 必须加 WHERE 不加 WHERE 会删除全表数据！
不释放表空间 DELETE 是逐行删除，删除后自增主键不会重置
可以回滚 DELETE 走事务，可以 ROLLBACK
大量删除会慢 一次性删除大量行可能导致锁表时间长

四、TRUNCATE（清空整张表）

TRUNCATE 也是删除，但属于 DDL 而非 DML。

TRUNCATE vs DELETE 对比

对比项 DELETE TRUNCATE
类型 DML DDL
能否加 WHERE ✅ ❌ 一刀切
自增主键 保留当前值继续递增 重置为 1
事务回滚 ✅ 可 ROLLBACK ❌ 不可回滚
执行速度 慢（逐行删） 快（直接重建表）
触发触发器 ✅ 触发 DELETE 触发器 ❌ 不触发

五、增删改通用规范

规范 说明
增删改之前先 SELECT 用同样的 WHERE 在 SELECT 里测一下，避免误伤
危险操作加事务 START TRANSACTION; → 执行 → COMMIT; 或 ROLLBACK;
重要数据先备份 大规模 UPDATE / DELETE 之前 mysqldump 一次
注意字符集 客户端编码要 utf8mb4，避免中文乱码
字段值类型 数字不加引号、字符串加单引号、日期加单引号
