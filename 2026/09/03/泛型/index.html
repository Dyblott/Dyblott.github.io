泛型

概述

泛型（Generics）是一种”类型参数化“的技术，用来统一数据类型，提高代码复用性，让编译器进行类型检查，减少强制类型转换。

格式： <E>、<T>、<K, V>、<R> 等均可，尖括号中只能是引用类型（基本类型要写对应的包装类）。

为什么要用泛型

不使用泛型的问题： 集合不指定类型时默认为 Object，取出元素需要手动强转，容易触发 ClassCastException。

使用泛型后： 编译器在编译阶段就做类型检查，取出时无需强转。

泛型的定义

1. 泛型类

将泛型定义在类名上，创建对象时确定类型。

2. 泛型方法

将泛型定义在方法声明上，调用方法时确定类型。

3. 泛型接口

将泛型定义在接口名上，实现类确定类型。

实现方式一： 实现时直接确定类型（类似 Scanner）

实现方式二： 实现时仍不确定，继续携带泛型（类似 ArrayList）

泛型通配符

? 代表未知类型，通常用在方法参数位置，接收任意类型的集合。

泛型的上限和下限

通过 <T> 或 ? 可以限制泛型的类型范围。

上限：<? extends 类型>

? 只能接收本类及子类类型。

下限：<? super 类型>

? 只能接收本类及父类类型。

记忆口诀：

  • extends → 上是天花板 → 最多到本类，向下扩展子类 → 读作”继承自”
  • super → 下是地下室 → 最多到本类，向上追溯父类 → 读作”超于”

应用场景：

  • 定义类 / 方法 / 接口时，类型不确定但知道范围 → 用泛型上限或下限约束
  • Collections.sort(list, comparator) 的 comparator 参数用了 super，允许传入 Comparator<Object> 来比较 String 元素

泛型注意事项

注意 说明
泛型只能是引用类型 ArrayList<int> ❌ → ArrayList<Integer> ✅
不写泛型默认为 Object ArrayList list = new ArrayList() 元素类型为 Object
泛型在编译阶段消除 运行时不保留泛型信息（类型擦除），因此 list.getClass() == list.getClass() 永远为 true
泛型类静态方法不能使用类上声明的泛型 静态方法需要单独声明 <E>，因为静态方法先于对象创建
