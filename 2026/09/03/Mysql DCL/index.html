MySQL DCL（数据控制语言）

概述

DCL（Data Control Language） 是 SQL 中用于控制数据库访问权限和事务行为的语言，核心是”谁能干什么”。

子类 关键字 作用
DCL GRANT、REVOKE、CREATE USER、DROP USER 权限管理
TCL（事务控制，常并入 DCL） COMMIT、ROLLBACK、SAVEPOINT 事务提交与回滚

MySQL 官方把事务控制归为 TCL（Transaction Control Language），但实际工作中常和 DCL 一起讲。

二、权限管理

1. 常用权限列表

权限 说明
ALL / ALL PRIVILEGES 除 GRANT 外所有权限
SELECT 查询
INSERT 插入
UPDATE 修改
DELETE 删除
CREATE 建库、建表
DROP 删库、删表
ALTER 改表结构
INDEX 创建/删除索引
REFERENCES 外键
GRANT OPTION 允许把自己的权限授予别人

2. 授予权限（GRANT）

数据库.表的写法：

写法 范围
*.* 所有库的所有表
mydb.* mydb 库的所有表
mydb.employee mydb 库的 employee 表
mydb.emp* mydb 库 emp 开头的表

3. 查看权限

4. 撤销权限（REVOKE）

⚠️ REVOKE 不能撤销”不存在”的权限；撤销 ALL 不会自动撤销 GRANT OPTION，需单独写一条。

5. 权限层级（重要）

层级 范围 例子
全局 整个 MySQL 实例 *.*
数据库 整个库 mydb.*
表 单张表 mydb.employee
列 表中部分列 SELECT (id, name) ON mydb.employee
存储过程 函数/过程 ROUTINE 权限
代理用户 模拟另一用户身份 PROXY

列权限要写在 SQL 中，语法较特殊，一般不用。GRANT SELECT(id, name) ON mydb.employee TO ... 不是标准用法，更多是通过视图间接实现。

三、权限生效与刷新

操作 是否需要刷新
GRANT / REVOKE / CREATE USER MySQL 8.0 自动生效，5.7 也基本实时
直接改 mysql.user 表 ⚠️ 必须 FLUSH PRIVILEGES;

3. 另开终端免密登录并清空密码

4. 重启服务

五、事务控制（TCL）

事务是一组要么全部成功、要么全部失败的 SQL 操作。InnoDB 引擎才支持事务。

1. 事务的 ACID 特性

特性 含义
Atomicity（原子性） 整体执行，要么全成，要么全败
Consistency（一致性） 事务前后数据状态合法
Isolation（隔离性） 并发事务互不干扰
Durability（持久性） 事务一旦提交，结果永久

2. 事务的基本使用

默认情况下 MySQL 是自动提交的（每条 SQL 独立提交），用 START TRANSACTION 后关闭自动提交。

3. 事务回滚点（SAVEPOINT）

4. 四种隔离级别（重要）

隔离级别 脏读 不可重复读 幻读 性能
READ UNCOMMITTED 读未提交 ✅ 有 ✅ 有 ✅ 有 最高
READ COMMITTED 读已提交（Oracle 默认） ❌ ✅ 有 ✅ 有 高
REPEATABLE READ 可重复读（MySQL 默认） ❌ ❌ ✅ 有 中
SERIALIZABLE 串行化 ❌ ❌ ❌ 最低

问题说明：

现象 解释
脏读 读到其他事务未提交的数据
不可重复读 同一事务中两次读同一行，结果不同（被其他事务 update/delete 了）
幻读 同一事务中两次查条件范围结果集行数不同（被其他事务 insert 了）

六、DCL 常用命令速查

用途 语法
创建用户 CREATE USER 'u'@'host' IDENTIFIED BY 'pwd';
删除用户 DROP USER 'u'@'host';
修改密码 ALTER USER 'u'@'host' IDENTIFIED BY 'new_pwd';
授予权限 GRANT 权限 ON 库.表 TO 'u'@'host';
撤销权限 REVOKE 权限 ON 库.表 FROM 'u'@'host';
查看权限 SHOW GRANTS FOR 'u'@'host';
刷新权限 FLUSH PRIVILEGES;
开启事务 START TRANSACTION;
提交事务 COMMIT;
回滚事务 ROLLBACK;
设置回滚点 SAVEPOINT 名字;
查隔离级别 SELECT @@transaction_isolation;

七、最佳实践

规范 建议
最小权限原则 应用账号只给 SELECT/INSERT/UPDATE/DELETE，不要 ALL
禁止用 root 连接应用 root 仅限 DBA 使用
强密码策略 长度 ≥ 12 位，含大小写+数字+特殊字符
远程连接要限制 '%' 要慎用，优先限定网段 192.168.1.%
定期审计 定期 SELECT user, host FROM mysql.user; 清理无用账号
重要操作开事务 UPDATE / DELETE 之前 START TRANSACTION;
了解默认隔离级别 MySQL 默认 REPEATABLE READ，开发中常见现象要能解释
