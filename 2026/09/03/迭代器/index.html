迭代器

概述

迭代器（Iterator） 是 Java 提供的一种统一遍历集合的方式。不管是 ArrayList、HashSet 还是 LinkedList，都可以用同一种方式取出元素。

  • 迭代器是一个接口 java.util.Iterator
  • Collection 接口提供了获取迭代器的方法：Iterator<E> iterator()
  • 所有的单列集合都可以通过 iterator() 获取自己的迭代器对象

迭代器的两个核心方法

方法 说明
boolean hasNext() 判断集合中是否还有下一个元素
E next() 取出下一个元素，同时将指针向后移动

使用步骤（固定套路）：

  1. 调用集合的 iterator() 方法，获取迭代器对象
  2. 使用 while 循环，判断 hasNext()
  3. 条件成立时，调用 next() 取出元素

迭代器的底层原理

以 ArrayList 为例：list.iterator() 返回的并不是 Iterator 接口本身，而是 ArrayList 内部的一个私有内部类对象 Itr。

注意：不同的集合，iterator() 返回的实现类不同（HashSet 底层是 HashMap 的迭代器，LinkedList 也有自己的实现），但它们都实现了 Iterator 接口，使用方式完全一样。

并发修改异常（重点）

需求： 集合中存储”唐僧、孙悟空、猪八戒、沙僧”，遍历时如果遇到”猪八戒”，往集合中添加”白龙马”。

为什么会抛异常？（底层原因）

集合内部维护了两个关键数值：

变量 含义
modCount 实际操作次数（集合被增删改一次就 +1）
expectedModCount 预期操作次数（创建迭代器时记录的 modCount 快照）

我们调用 list.add("白龙马") 时，add 方法内部会执行 modCount++，导致实际操作次数发生变化：

此时 modCount != expectedModCount，下一次 next() 就抛出了并发修改异常。

结论：

在使用迭代器遍历集合的过程中，不要随意修改集合的长度（增、删）。迭代器和集合的修改必须”步调一致”，否则会触发并发修改异常。

解决方式一：ListIterator

ListIterator 是 Iterator 的子接口，专门给 List 集合使用，它自带 add() 方法——通过迭代器自己的方法去修改集合，迭代器会同步更新预期次数，不会抛异常。

ListIterator 的常用方法：

方法 说明
boolean hasNext() 是否有下一个
E next() 获取下一个
boolean hasPrevious() 是否有上一个（可反向遍历）
E previous() 获取上一个
void add(E e) 在当前位置添加元素（不会抛并发修改异常）
void set(E e) 替换上一次 next/previous 返回的元素
void remove() 删除上一次 next/previous 返回的元素

迭代器与增强 for

增强 for 遍历集合的底层原理就是迭代器。

底层原理总结：

遍历对象 增强 for 的底层
数组 普通 for 循环
集合 迭代器 Iterator

正因为增强 for 遍历集合底层是迭代器，所以在增强 for 中修改集合长度，同样会触发并发修改异常。

三种遍历方式对比

遍历方式 写法 特点
普通 for for (int i = 0; i < list.size(); i++) 只能用于有索引的集合（List），可拿到索引
增强 for for (String s : list) 代码最简洁，底层是迭代器，无索引
迭代器 while (it.hasNext()) 通用性强，遍历中可安全删除元素

选择建议：

  • 只是遍历打印 → 增强 for
  • 需要索引 → 普通 for
  • 遍历时需要删除元素 → 迭代器 + it.remove()
  • 遍历时需要添加元素 → ListIterator + lit.add()
