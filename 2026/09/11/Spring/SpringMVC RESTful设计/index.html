SpringMVC RESTful 设计

1. RESTful 是什么

REST（Representational State Transfer） 即”表现层状态转化”，是一种软件架构设计风格。RESTful 是遵循 REST 原则设计的 API。

核心理念：把一切看成资源，用 HTTP 原有的方法（GET/POST/PUT/DELETE）来表达对资源的操作。

操作 传统方式 RESTful 方式
查询用户列表 GET /getUsers GET /users
查询单个用户 GET /getUserById?id=1 GET /users/1
新增用户 POST /addUser POST /users
修改用户 POST /updateUser?id=1 PUT /users/1
删除用户 POST /deleteUser?id=1 DELETE /users/1

2. RESTful 核心原则

原则 说明 示例
资源化 一切皆资源，用名词（不用动词） /users、/orders、/products
HTTP 方法对应操作 GET 查、POST 增、PUT 改、DELETE 删 见上方表格
层次化 资源嵌套表示关系 /users/1/orders（用户1的所有订单）
无状态 每次请求都是独立的，服务器不保存会话状态 依赖 Token 鉴权

4. 路径参数 vs QueryString 参数

类型 格式 用途 示例
路径参数 /users/{id} 标识特定资源（主键） GET /users/123
QueryString /users?page=1&size=10 筛选、排序、分页等辅助参数 GET /users?status=1&sort=name

记忆口诀：路径参数是资源的身份证号（必须有），QueryString 是筛选条件（可没有）。

6. 状态码设计

RESTful 风格的 API 要合理使用 HTTP 状态码：

状态码 含义 RESTful 场景
200 OK 成功（查询/更新/删除成功）
201 Created 资源创建成功（POST 新增）
204 No Content 删除成功但无返回体
400 Bad Request 参数格式错误、业务校验失败
401 Unauthorized 未登录、未认证
403 Forbidden 无权限
404 Not Found 资源不存在
409 Conflict 资源冲突（如手机号已注册）
422 Unprocessable Entity 语义错误（如邮箱格式对但邮箱不存在）
500 Server Error 服务器内部错误

9. RESTful 命名规范

规范 正确示例 错误示例
用复数名词表示资源 /users、/orders /getUser、/user
用小写字母 /user-orders /userOrders
用连字符分隔 /user-orders /user_orders
不暴露实现细节 /items /itemsDAO
路径参数放最后 /users/{id} /{id}/users
嵌套最多 2~3 层 /users/1/orders /users/1/orders/2/items/3

10. 总结

知识点 核心要点
RESTful 是什么 把一切看成资源，用 HTTP 方法操作资源
核心原则 资源化、HTTP 方法对应操作、层次化、无状态
路径参数 标识特定资源（主键），格式 /users/{id}
QueryString 筛选/分页/排序等辅助参数
分页 统一 PageResult<T> 结构返回
状态码 HTTP 状态码 + 业务码双保险
资源嵌套 层级关系用多级路径 /users/{userId}/orders
版本管理 路径版本 /v1/users
命名规范 复数名词、小写、连字符分隔、不超过3层嵌套
