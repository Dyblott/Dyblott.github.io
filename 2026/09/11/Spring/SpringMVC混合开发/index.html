SpringMVC 混合开发

1. 两种 Web 开发模式概览

Web 项目有两种主流开发模式，理解它们的差异是学好 SpringMVC 的基础。

1.1 前后端分离模式

核心定义：前端（页面渲染、用户交互）与后端（业务逻辑、数据存储）完全独立开发、独立部署，二者仅通过接口交互。

核心特点：

  • 技术栈独立：前端用 Vue/React/Uniapp，后端用 Java/Go/Python，团队可并行工作
  • 通信方式：基于 RESTful API，数据统一用 JSON
  • 核心优势：解耦度高、维护成本低、支持多端适配（一套后端接口对接网页/APP/小程序）
  • 典型流程：用户输入账号密码 → 前端调 /login 接口（传 JSON）→ 后端返回 JSON 结果 → 前端自行渲染页面

1.2 混合 Web 开发模式

核心定义：前端页面模板与后端业务代码集成在同一个项目，共享一套技术栈（如 Java + JSP/Thymeleaf），由后端直接控制页面渲染和数据传递。

核心特点：

  • 代码高度集成：页面模板（JSP/Thymeleaf）与 Controller 在同一工程，后端通过”共享域”（Request/Session）传递数据
  • 渲染方式：后端处理完业务，直接把数据嵌入页面模板，生成完整 HTML 返回浏览器
  • 核心优势：技术栈统一、开发部署简单（只部署一个项目）、学习成本低
  • 核心局限：耦合度高（改页面可能要动后端）、扩展性差、难适配多端
  • 典型流程：访问 /user/list → 后端查数据 → 存入 Request 域 → JSP/Thymeleaf 用 ${user.name} 嵌入 → 返回完整 HTML

一句话区分：前后端分离 = “后端出数据、前端做渲染”；混合开发 = “后端既出数据又渲染页面”。

1.3 核心对比表

对比维度 前后端分离模式 混合 Web 开发模式
核心定义 仅提供数据接口，不参与页面渲染 集成页面模板与业务逻辑，主导页面渲染
后端参数接收 queryString / path / json queryString / path / json
数据传递方式 无共享域，仅接口返回数据 依赖共享域（Request/Session/Application）
模板语言 不使用（前端自行渲染） 依赖 JSP/Thymeleaf/Freemarker
转发/重定向 无（前端自主控制跳转） 核心操作（后端控制页面流转）
响应格式 统一返回 JSON 返回完整 HTML 页面
后端核心输出 结构化数据（接口结果） 完整渲染的 HTML 页面
适用场景 中大型项目、多端产品 小型项目、内部系统、快速开发

3. 转发与重定向（页面跳转）

转发和重定向是混合开发中页面跳转的核心方式（如登录成功后跳首页、查询失败跳错误页）。

3.1 核心区别

对比维度 转发（Forward） 重定向（Redirect）
HTTP 请求次数 1 次 2 次
浏览器地址栏 URL 保持不变 URL 更新为新地址
跳转范围 仅当前应用内部 可跨应用/外部 URL
数据共享 Request 域有效 Request 域失效（用 Session）
典型场景 应用内页面跳转 防表单重复提交、跨应用跳转

3.2 转发语法

访问 /jump/toForward，地址栏仍是 /jump/toForward，页面显示 forward-page.html 内容。

3.3 重定向语法

访问 /jump/toRedirect，地址栏变为 /jump/showRedirect，页面显示 redirect-page.html 内容。

更详细的转发/重定向讲解（含 Model 传值、RedirectAttributes）见《SpringMVC响应处理与JSON》。

4. 共享域技术（数据传递）

跳转时普通局部变量无法跨方法/跨请求传递数据，共享域是服务器提供的全局数据存储容器，专门解决跳转过程中的数据传递。

4.1 三类共享域

共享域 作用范围 跳转支持
Request 域 仅单次 HTTP 请求内有效（请求结束即销毁） 仅转发有效
Session 域 一次用户会话内有效（浏览器未关/未超时） 转发+重定向均有效
ServletContext 域 整个应用生命周期内有效（全局共享，重启失效） 所有跳转均有效

原则：优先选作用域小的（Request > Session > ServletContext），减少资源占用和冲突。

4.2 Request 域实战（单次请求）

刷新页面后 Request 域数据消失（单次请求有效）。

4.3 Session 域实战（会话内）

关闭浏览器前，刷新/访问其他页面 Session 数据仍在（会话内有效）。

4.4 ServletContext 域实战（全应用）

重启 Spring Boot 项目后全局数据消失（应用生命周期内有效）。

共享域 Thymeleaf 取值语法
Request 域 ${key}
Session 域 ${session.key}
ServletContext 域 ${application.key}
Model（本质也是 Request 域） ${key}

5. Cookie（客户端存储）

Cookie 是客户端浏览器的本地存储（不是服务端共享域），数据存在用户浏览器中。

核心特点：

  • 存储位置：客户端本地
  • 作用范围：可配置有效期（秒/天），未过期关闭浏览器仍有效
  • 跳转支持：转发/重定向均有效，甚至跨会话
  • 适用场景：长期保存的非敏感数据（记住登录状态、用户偏好）

实战：设置与读取 Cookie

⚠️ 安全提示：Thymeleaf 3.1+ 出于安全考虑，默认不再允许模板中直接访问 #request、#session 等，敏感数据不要放 Cookie。

6. 如何选择开发模式

场景 推荐模式 理由
中大型互联网项目 前后端分离 解耦、多端适配、易维护
内部管理系统 混合开发 开发快、部署简单、学习成本低
快速原型/MVP 混合开发 一套技术栈搞定前后端
需要对接 APP/小程序 前后端分离 一套后端接口多端复用
老旧系统维护 混合开发（JSP） 历史代码兼容性

7. 总结

知识点 核心要点
两种模式 前后端分离（出数据）+ 混合开发（出数据又渲染）
混合开发核心 @Controller + Thymeleaf 模板引擎
转发 服务器内部1次请求，URL不变，Request 域有效
重定向 浏览器2次请求，URL更新，需用 Session 传值
共享域 Request（单次）> Session（会话）> ServletContext（全局）
Thymeleaf 取值 ${key} / ${session.key} / ${application.key}
Cookie 客户端存储，跨会话有效，注意安全
选型原则 大项目分离、小项目/内管混合
