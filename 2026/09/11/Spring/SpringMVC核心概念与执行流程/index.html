SpringMVC 核心概念与执行流程

1. SpringMVC 是什么

SpringMVC 是 Spring 家族中专门做Web 层开发的框架，核心职责是接收浏览器请求、调用业务代码、返回响应结果。

一句话理解：SpringMVC = Spring（生态）+ MVC（设计模式），专治 Web 层各种麻烦。

为什么选 SpringMVC？

优点 说明
Spring 家族原生产品 与 IOC 容器无缝对接
覆盖全面 请求映射、参数接收、视图解析、JSON 处理、异常处理全覆盖
代码简洁 注解驱动，开发效率高
组件可插拔 想用什么功能配相应组件即可
性能出色 适合大型互联网项目

2. MVC 是什么

MVC 是软件工程中的一种架构设计模式，把代码分成三层：

字母 含义 职责 对应 SpringMVC
M Model 封装数据、业务逻辑 JavaBean / Service
V View 负责展示页面 JSP / Thymeleaf / HTML
C Controller 接收请求、调用 Service、返回视图 @Controller 类

通俗理解：Controller 是”接单员”（接收请求），Service 是”厨师”（处理业务），Model 是”盘子”（装数据），View 是”展示柜”（呈现给用户看）。

3. SpringMVC 执行流程（核心·必背）

SpringMVC 采用了前端控制器模式，所有请求都先经过 DispatcherServlet（前端控制器），再分发到具体处理器。

记忆口诀：前端控制器（入口）→ 映射器（找方法）→ 适配器（执行方法）→ 控制器（写业务）→ 视图解析器（找页面）→ 视图（展示）→ 返回。

5. 核心组件一览

组件 作用 是否需要手动配置
DispatcherServlet 前端控制器，统一入口 Spring Boot 自动配置
HandlerMapping 根据 URL 找 Handler 自动（扫描注解）
HandlerAdapter 执行 Handler 自动
Controller 业务逻辑 手动写
ViewResolver 解析视图路径 自动配置
View 渲染页面 手动写 JSP/Thymeleaf
HandlerExceptionResolver 全局异常处理 可自动配置
Converter / Formatter 数据转换 自动
ContentNegotiationManager 内容协商 自动

6. @RestController 进阶说明

@RestController 是 @Controller + @ResponseBody 的合体，但注意：类上加 @ResponseBody 会让每个方法的返回值都直接作为响应体返回，不会走视图解析器。

7. 总结

知识点 核心要点
SpringMVC Spring 家族 Web 层框架，核心是前端控制器模式
MVC M=数据/业务、V=页面、C=接收请求
执行流程 DispatcherServlet → HandlerMapping → HandlerAdapter → Controller → ViewResolver → View
Spring Boot 整合 导入 spring-boot-starter-web 即可，自动配置全部组件
@RestController @Controller + @ResponseBody，适合纯数据接口
@Controller 适合需要跳转页面的场景
