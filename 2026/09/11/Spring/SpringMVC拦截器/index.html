SpringMVC 拦截器

1. 拦截器是什么

拦截器（Interceptor） 是 SpringMVC 提供的组件，作用是在请求到达 Controller 之前和响应返回之前做拦截处理。

典型使用场景：

  • 登录验证（没登录就拦截，跳转登录页）
  • 权限校验（没有操作权限就拒绝）
  • 日志记录（记录每个请求的访问时间、参数）
  • 性能监控（记录接口耗时）
  • 请求预处理（统一处理参数、编码等）

2. 拦截器 vs Filter（重要对比）

对比项 Filter（过滤器） Interceptor（拦截器）
来源 Servlet 规范 SpringMVC 独有
作用范围 所有请求（Servlet/JSP/静态资源） 仅 SpringMVC 管理的请求
配置位置 web.xml 或 @WebFilter Spring 配置类
执行顺序 Filter 链（web.xml 顺序） HandlerInterceptor 数组
获取 Spring Bean ❌ 不能直接获取 ✅ 可以（Spring 容器管理）
能否拦截静态资源 ✅ 能 ❌ 不能（DispatcherServlet 不处理的资源）
典型用途 字符编码、全局安全、CORS 业务级拦截（登录、权限）

记忆口诀：Filter 是”门卫”（公司大门，管所有进出），Interceptor 是”前台”（只管来办事的人）。

7. preHandle 返回 false 的效果

当某个拦截器的 preHandle 返回 false 时：

  1. 该拦截器之后的所有拦截器的 preHandle 不再执行
  2. Controller 不执行
  3. 后续拦截器的 postHandle 和 afterCompletion 不执行
  4. 已执行过 preHandle 的拦截器的 afterCompletion 会执行（清理资源用）

9. 拦截器与全局异常处理

拦截器的 preHandle 发生异常时，不会进入 @ExceptionHandler 的异常处理，而是由 Servlet 容器直接处理。

解决方案：在 preHandle 中用 try-catch 包裹，或者改用 Spring 的 @ControllerAdvice 全局异常处理。

10. 总结

知识点 核心要点
拦截器是什么 请求到达 Controller 之前和响应返回之前的拦截处理组件
三个方法 preHandle（前置）→ Controller → postHandle（后置）→ afterCompletion（最终）
preHandle 返回 false 短路，后续都不执行
与 Filter 的区别 Filter 管所有请求，Interceptor 只管 SpringMVC 请求；Interceptor 能用 Spring Bean
注册方式 实现 HandlerInterceptor + 配置类注册 + 配拦截路径
路径规则 /*、/**、/user/*、/user/**
多个拦截器顺序 preHandle 正序，postHandle/afterCompletion 倒序
