SpringMVC 异常处理

1. 为什么要全局异常处理

没有统一异常处理时，代码出错会让用户看到丑丑的堆栈信息，体验很差，还暴露了服务器结构（安全隐患）。

2. @ExceptionHandler — 单个 Controller 内异常处理

作用范围：只处理当前 Controller 里的异常。

⚠️ @ExceptionHandler 只管当前 Controller，不同 Controller 之间不能共享，需要用全局异常处理。

3. @ControllerAdvice — 全局异常处理器（重点）

@ControllerAdvice（或 @RestControllerAdvice）标注的类，可以拦截项目中所有 Controller 的异常，是实际开发中的标准做法。

5. @ResponseStatus — 快速指定 HTTP 状态码

对于特定异常，想直接返回特定 HTTP 状态码，可以用 @ResponseStatus 注解：

注意：@ResponseStatus 直接控制 HTTP 状态码，适合简单场景；复杂场景（需要返回 JSON 详情）用 @ControllerAdvice 更灵活。

6. 处理不同类型的异常

@ExceptionHandler 支持精确匹配异常类型，匹配规则是从子类到父类（就近匹配）。

⚠️ 顺序很重要：@ExceptionHandler 的匹配是从上到下就近匹配，写在最前面的最精确，写在最后面的最宽泛（兜底）。子类异常写在父类异常前面。

10. 总结

知识点 核心要点
@ExceptionHandler 处理单个 Controller 的异常
@ControllerAdvice 全局异常处理器，拦截所有 Controller
@RestControllerAdvice @ControllerAdvice + @ResponseBody，适合前后端分离
自定义 BusinessException 带错误码的业务异常，统一错误码管理
@ResponseStatus 快速指定 HTTP 状态码
匹配顺序 就近匹配（子类异常在前，父类兜底在后）
全局数据绑定 @ModelAttribute 统一注入公共数据
@InitBinder 全局数据预处理（日期等特殊类型）
