SpringMVC 参数接收

1. 参数接收总览

SpringMVC 支持从多个位置接收参数，核心规则是”参数名 = 形参名”自动匹配：

接收方式 参数位置 示例
直接接收 URL ?key=value ?username=zhangsan
@RequestParam URL ?key=value 显式指定参数名、控制必填
实体类接收 URL ?key=value 批量接收，自动映射
@PathVariable URL 路径中 /user/123
@RequestBody 请求体（JSON） POST JSON 数据
@RequestHeader 请求头 取 Header 值
@CookieValue Cookie 取 Cookie 值

2. 方式一：直接接收 QueryString 参数

最简单的方式：形参名 = URL 参数 key，直接写就行。

规则：

  • 形参名和 URL 参数 key 一致就能自动收到
  • 没传参数 → 形参值为 null（所以不要用 int，要用 Integer）
  • 形参名和 key 不一致 → 收到 null

⚠️ 踩坑：int id 用 Integer id，因为前端不传时 null 不能赋值给基本类型，会报 500 错误。

3. 方式二：@RequestParam 注解

当直接接收不够用时，用 @RequestParam 做更精细的控制。

三大功能：

功能 写法 说明
指定参数映射名 @RequestParam("stuAge") int age 形参名和 URL key 不同时用
控制是否必传 required = true（默认） 必填参数没传 → 400 错误
设置默认值 defaultValue = "18" 未传时使用默认值

实际开发经验：大部分参数都用 @RequestParam 显式标注，配合 required = false, defaultValue = "..." 使用，避免前端漏传导致 400 错误。

4. 方式三：实体类接收

当参数很多时，用实体类接收，不用一个一个写形参，代码更简洁。

规则：实体类属性名 = URL 参数 key（自动按 setXxx 注入）。

实体类接收的必备条件：

  1. 属性名 = URL 参数 key
  2. 有无参构造器（Lombok @Data 会自动生成）
  3. 有 getXxx / setXxx 方法

5. 方式四：@PathVariable 路径参数

路径参数是嵌在 URL 路径里的动态值，用 {占位符} 标记，用 @PathVariable 接收。

典型 RESTful 风格：/user/123 → 查 ID 为 123 的用户

方式 参数位置 关键注解 适用场景
直接接收 URL ?key=value 无 参数少、简单接口

10. 常见错误与解决

错误 原因 解决
500 + 参数类型错误 用 int 接收了 null 改用 Integer
400 参数缺失 @RequestParam(required=true) 没传 检查前端参数，或加 defaultValue
404 路径不存在 路径参数少了 /{id} 检查 URL 和 @PathVariable 注解
参数名不匹配收到 null 形参名和 URL key 不一致 用 @RequestParam("key名") 或改实体类属性名
一名多值绑定失败 没加 @RequestParam 给 List/数组 加 @RequestParam
