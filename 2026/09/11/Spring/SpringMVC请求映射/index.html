SpringMVC 请求映射

1. @RequestMapping 基础

@RequestMapping 是 SpringMVC 中最核心的注解，作用是把一个 URL 地址映射到具体的 Controller 方法上。

浏览器访问 /hello → SpringMVC 找到对应方法 → 执行 → 返回结果。

2. 路径匹配：精准 vs 模糊

2.1 精准匹配（最常用）

URL 完全一致才匹配：

2.2 模糊匹配（通配符）

通配符 说明 示例
* 匹配单层任意字符 /product/* → 匹配 /product/aaa，不匹配 /product/a/b
** 匹配任意层任意字符 /product/** → 匹配 /product/a/b/c

开发中精准匹配最常用，模糊匹配适合做”统一前缀 + 批量处理”。

3. 类级别 + 方法级别组合映射

@RequestMapping 可以同时标注在类和方法上：

  • 类上：提取所有方法的通用路径前缀
  • 方法上：配置具体路径（相对于类前缀拼接）

好处：改一处前缀，所有方法路径都自动更新，代码更整洁。

4. 请求方法限制

@RequestMapping 默认所有 HTTP 方法都接受（GET/POST/PUT/DELETE…），可以通过 method 属性限制。

405 Method Not Allowed = 请求方法写错了，比如接口只支持 POST，你却用 GET 访问。

5. 快捷注解（推荐使用）

SpringMVC 提供了一组快捷变体注解，代替 method = RequestMethod.XXX，语义更清晰。

快捷注解 等价写法 适用场景
@GetMapping @RequestMapping(method=GET) 查询
@PostMapping @RequestMapping(method=POST) 新增
@PutMapping @RequestMapping(method=PUT) 全量更新
@DeleteMapping @RequestMapping(method=DELETE) 删除
@PatchMapping @RequestMapping(method=PATCH) 部分更新

开发中强烈推荐用快捷注解，比 @RequestMapping(method=...) 更简洁、更易读：

RESTful 风格推荐写法：@GetMapping("/list") 可以简写为 @GetMapping（当路径为空时，等于类路径本身，即 /user/list）。但为可读性，建议显式写清楚。

9. 总结

知识点 核心要点
@RequestMapping URL → Controller 方法的核心映射
精准/模糊匹配 精准最常用，* 单层，** 任意层
类+方法组合 类上写前缀，方法上写具体路径
method 限制 默认所有方法，用 method 限制可避免误用
快捷注解 推荐：@GetMapping / @PostMapping / @PutMapping / @DeleteMapping
映射冲突 同路径+同方法会冲突，路径+方法组合必须唯一
