Servlet 与 JavaBean

1. 先搞清楚几个概念

概念 说明
Web 服务器 能接收 HTTP 请求并返回响应的软件（nginx、Apache、Tomcat）
Servlet 容器 专门管理 Servlet 的运行环境，本质也是 Web 服务器
Servlet 跑在容器里、接收请求返回响应的 Java 程序（没有 main，不能自己跑）

一句话理解：Tomcat 是”大房子”，Servlet 是住在大房子里的”小程序”。房子负责接待客人（解析请求），小程序负责处理业务。

常见 Servlet 容器：

容器 特点
Tomcat（Apache） 最主流，SpringBoot 默认内嵌
Jetty（Eclipse） 轻量，适合嵌入式
Undertow（Red Hat） 高性能，SpringBoot 可选

容器帮 Servlet 干了哪些活？

  1. 网络通信：解析 HTTP 请求、封装响应
  2. 生命周期：创建 Servlet、调用 init / service / destroy
  3. 多线程：每个请求分配一个线程
  4. 类加载：动态加载 Servlet 类

2. 第一个 Servlet

2.1 用注解写（Servlet 3.0+，无需 web.xml）

三个要点：

  • 继承 HttpServlet，重写 doGet / doPost
  • @WebServlet("/hello") 是 Servlet 3.0+ 注解，替代 web.xml 配置
  • HttpServletRequest 拿请求参数，HttpServletResponse 写回响应

⚠️ 不要自己 new Servlet()！Servlet 由容器创建和管理，自己 new 出来的没有容器环境，跑不起来。

3. Servlet 生命周期

方法 调用次数 何时调用
init() 1 次 第一次请求到达时
service() 每次请求 每次请求
destroy() 1 次 服务器关闭时

记忆口诀：init 生一次，service 服务每一次，destroy 死一次。

4. 请求与响应对象

4.1 HttpServletRequest（请求对象）

4.2 HttpServletResponse（响应对象）

记忆口诀：转发是”服务员帮你递纸条”（一次请求，数据一起带）；重定向是”告诉你房间号你自己去”（两次请求，数据清空）。

5. JavaBean 是什么

JavaBean 就是符合特定规范的普通 Java 类，核心用途：封装数据。

三件套规范（必须全部满足）：

规范 说明
public 类 能被外部访问
private 属性 数据封装，不直接暴露
公共无参构造器 框架靠反射创建对象，调的就是这个
public getter/setter 提供受控访问

7. 相关名词扫盲

名词 定位 说明
JavaBean 规范 无参构造 + getter/setter，可重用组件
POJO 普通 Java 对象 无框架约束的简单类
Entity 实体类 与数据库表一一对应
DTO 数据传输对象 层与层之间传参
VO 视图对象 给前端展示用

8. 与 Spring Boot 的关系（衔接到下一阶段）

对比 传统 Tomcat 部署 Spring Boot
部署方式 WAR 包部署到 Tomcat 内嵌 Tomcat，jar 直接运行
启动命令 startup.bat java -jar app.jar
容器管理 手动 自动

核心思想一致：Servlet 归 Tomcat 管，Spring Bean 归 Spring 容器管——都是”容器管理对象”。

9. 避坑速查

坑 后果 解决
javax vs jakarta ClassNotFoundException Tomcat 9 用 javax.servlet，10+ 用 jakarta.servlet
自己 new Servlet 运行不起来 Servlet 由容器创建，不能 new
删掉无参构造器 InstantiationException 框架反射创建对象靠它
boolean 写成 getVip() 框架找不到属性 boolean 的 getter 写 isVip()

参数取出来乱码 POST 表单乱码 req.setCharacterEncoding("UTF-8")（取参数前设）
