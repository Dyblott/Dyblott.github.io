Tomcat 详解

1. Tomcat 是什么

Tomcat 是 Apache 开源的 Servlet 容器 + HTTP 服务器，用 Java 编写。

核心职责一句话：浏览器发请求 → Tomcat 接收并解析 → 找到对应的 Servlet 执行 → 把结果返回给浏览器。

通俗理解：Tomcat 就是一个”大房子”，Servlet 是住在里面的”小程序”。浏览器敲门，房子里的 Servlet 负责接待。

版本对照（选 Tomcat 9 最稳）：

Tomcat Java Servlet JSP
Tomcat 7 JDK 6+ Servlet 3.0 JSP 2.2
Tomcat 8 JDK 7+ Servlet 3.1 JSP 2.3
Tomcat 9 JDK 8+ Servlet 4.0 JSP 2.3
Tomcat 10 JDK 11+ Servlet 5.0（jakarta） JSP 3.0

⚠️ 跨版本大坑：Tomcat 10+ 把 javax.servlet 全部改名为 jakarta.servlet，旧项目迁移必须批量替换包名。

2. Tomcat 目录结构

记忆口诀：bin 启动、conf 配置、webapps 部署、logs 查错、work 放 JSP 翻译后的类。

关键目录详解：

目录 核心文件 作用
conf/ server.xml 改端口、配虚拟主机
conf/ web.xml MIME类型、默认servlet、欢迎页
logs/ catalina.out 启动日志、异常堆栈（必看）
logs/ localhost.日期.log 当前应用 filter/servlet 输出
webapps/ — 把项目扔这里就自动部署

3.1 目录结构

⚠️ 页面放 WEB-INF/pages/ 下，不能直接用 URL 访问，必须通过 Servlet 跳转。

3.2 部署方式

方式一：直接扔文件夹（最简单）

把项目文件夹复制到 webapps/ 下，Tomcat 启动时自动扫描并部署。

访问：http://localhost:8080/myapp/index.html

方式二：打 WAR 包（生产推荐）

WAR = Web Application Archive，本质是 ZIP 包，包含了整个 Web 应用。IDEA Run 按钮背后也是自动打成 WAR 放进 Tomcat。

4. Servlet 生命周期

三个生命周期方法：

方法 调用次数 何时调用
init() 1 次 第一次请求到达时
service() 每次请求 每次请求
destroy() 1 次 服务器关闭时

记忆口诀：init 生一次，service 服务每一次，destroy 死一次。

5. ServletConfig 与 ServletContext

对象 作用域 生命周期 作用
ServletConfig 单个 Servlet Servlet 创建→销毁 读取该 Servlet 的初始化参数
ServletContext 整个应用 服务器启动→关闭 全局共享数据、读取全局配置

记忆口诀：ServletConfig 配单个 Servlet（一把钥匙开一把锁），ServletContext 配整个应用（万能钥匙开所有门）。

6.1 HttpServletRequest 常用方法

6.2 HttpServletResponse 常用方法

记忆口诀：转发是”服务器内部递纸条”（一次请求，数据一起带过去）；重定向是”告诉你地址你自己去”（两次请求，数据清空）。

6.3 常见 HTTP 状态码

状态码 含义 常见场景
200 OK 正常响应
302 重定向 resp.sendRedirect()
400 Bad Request 参数格式错误
404 Not Found 路径写错、资源不存在
500 Internal Server Error 服务器代码异常
503 Service Unavailable 服务器过载

8. 常见错误排查

错误 1：端口被占用

错误 2：JAR 包冲突

表现：ClassNotFoundException 或 NoSuchMethodError

原因：多个 JAR 包里有同名的类，JVM 只加载第一个。

方案：

  1. 删掉重复的 JAR
  2. 检查是否有多余的旧版 Servlet API jar，不要打包进项目（scope 设为 provided）

错误 3：乱码

场景 解决
POST 表单乱码 req.setCharacterEncoding("UTF-8")（读取参数前调用）
响应中文乱码 resp.setContentType("text/html;charset=UTF-8")
URL 中文乱码 server.xml 加 URIEncoding="UTF-8"

错误 4：HttpServlet not found

原因：缺少 Servlet API jar。

错误 5：热部署后还是旧代码

Tomcat 缓存了编译后的 class。解决方案：

  1. shutdown.bat 关闭
  2. 删除 work/Catalina/localhost/项目名/ 下的缓存
  3. startup.bat 重启

9. 生产部署注意事项

  1. Linux 后台运行：nohup ./startup.sh &（防止 SSH 断开进程退出）
  2. 内存调优（bin/setenv.sh）：
  3. 删除默认应用：webapps/docs、webapps/examples、webapps/manager（安全风险）
  4. 必须用 shutdown.bat 正常关闭，直接关闭窗口端口可能不释放

10. 避坑速查表

坑 后果 解决
端口被占用 启动失败 netstat -ano 查进程，杀掉或改端口
javax vs jakarta ClassNotFoundException Tomcat 9 用 javax.*，10+ 用 jakarta.*
servlet-api 打入 WAR 运行时冲突 Maven scope 设为 provided
JAR 冲突 NoSuchMethodError 删重复包
热部署后旧代码 缓存未清 删除 work/ 目录
响应中文乱码 页面显示 ??? 先设 charset=UTF-8 再写内容
直接关闭窗口 端口未释放 必须用 shutdown.bat
