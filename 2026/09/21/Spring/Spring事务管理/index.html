Spring事务管理

1. 什么是事务

事务是逻辑上的一组操作，这组操作要么全部成功，要么全部失败回滚。

ACID 特性：

  • 原子性（Atomicity）：事务是不可分割的最小单元，要么都做，要么都不做。
  • 一致性（Consistency）：事务前后，数据从一个一致状态变到另一个一致状态。
  • 隔离性（Isolation）：多个事务并发执行时，一个事务不应被其他事务干扰。
  • 持久性（Durability）：事务一旦提交，对数据的修改是永久性的。

2. Spring 事务的两种管理方式

2.1 编程式事务

通过 TransactionTemplate 或 PlatformTransactionManager 手动控制事务边界。

缺点：侵入业务代码，冗余且不优雅。一般不推荐。

2.2 声明式事务（推荐）

基于 AOP 实现，将事务管理逻辑与业务代码解耦。两种方式：

  • 注解方式：@Transactional（最常用）
  • XML 配置方式：<tx:advice> + <aop:config>

3. 事务管理器 PlatformTransactionManager

Spring 并不直接管理事务，而是提供统一的 PlatformTransactionManager 接口，由具体持久层框架的实现类负责：

实现类 适用场景
DataSourceTransactionManager JDBC、MyBatis
HibernateTransactionManager Hibernate
JpaTransactionManager JPA
JtaTransactionManager 分布式/多数据源（JTA）

5. 七种事务传播行为（Propagation）

传播行为解决：一个事务方法被另一个事务方法调用时，事务如何传播。

传播行为 说明
REQUIRED（默认） 有事务就加入，没有就新建
REQUIRES_NEW 挂起当前事务，新建独立事务，互不干扰
SUPPORTS 有事务就加入，没有就以非事务方式运行
NOT_SUPPORTED 以非事务方式运行，挂起当前事务
MANDATORY 必须有事务，否则抛异常
NEVER 必须无事务，否则抛异常
NESTED 有事务则在其内开启嵌套（保存点）子事务

6. 隔离级别（Isolation）

解决并发事务带来的脏读、不可重复读、幻读问题。

隔离级别 脏读 不可重复读 幻读
READ_UNCOMMITTED ❌ ❌ ❌
READ_COMMITTED ✅ ❌ ❌
REPEATABLE_READ ✅ ✅ ❌
SERIALIZABLE ✅ ✅ ✅
DEFAULT 使用数据库默认（MySQL 一般为 REPEATABLE_READ）

✅ 表示可防止，❌ 表示可能出现。级别越高安全性越强，但性能越低。

7. 回滚规则

默认规则：

  • RuntimeException 及其子类 + Error：自动回滚
  • 受检异常（Exception 但不继承 RuntimeException）：默认不回滚

8. 常见坑：自调用失效

@Transactional 基于代理实现。同类内部方法互相调用时，绕过了代理，事务注解会失效。

解决方案：

  1. 拆分为两个 Service，通过依赖注入互相调用；
  2. 注入自身代理（@Autowired private UserService self; 再 self.methodB()）；
  3. 使用 AopContext.currentProxy() 获取代理后调用。

10. 小结

  • 日常开发优先使用 @Transactional 声明式事务；
  • 传播行为重点关注 REQUIRED 与 REQUIRES_NEW；
  • 注意默认只对 RuntimeException 回滚，受检异常需显式配置；
  • 警惕 同类自调用导致事务失效；
  • 纯查询方法建议加 readOnly = true 提升性能。
