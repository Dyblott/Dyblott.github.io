Spring 三层架构

一、什么是三层架构

三层架构是一种经典的软件分层设计思想，将应用程序按照职责划分为三个层次，各层之间职责单一、上层依赖下层、通过接口解耦。

二、各层职责

层次 名称 包名惯例 核心职责 常用技术
表现层 Presentation Layer controller 接收前端请求、参数校验、封装响应、调用业务层 SpringMVC / Spring Boot、@RestController
业务层 Business Layer service 实现业务规则、组合多个 DAO 操作、事务管理 @Service、@Transactional
持久层 Persistence Layer dao / mapper / repository 与数据库交互，完成增删改查 MyBatis、Spring Data JPA、JDBC

补充：实际项目通常还有实体层（entity / domain / pojo）存放数据模型，以及 dto/vo 用于层与层之间的数据传输，但它们不属于三层架构的核心分层。

三、分层调用规则

  1. 调用方向：Controller → Service → Dao → 数据库，严禁跨层调用（如 Controller 直接调 Dao）。
  2. 依赖接口：Service 层面向接口编程（UserService 接口 + UserServiceImpl 实现类），便于解耦和替换实现。
  3. 单向依赖：下层不知道上层的存在，只被上层调用。
  4. 数据传递：各层之间通过实体对象（Entity/DTO/VO）传递数据。

五、为什么要分层

优点 说明
职责单一 每层只做自己的事，代码清晰、易读
解耦 上层只依赖下层接口，替换实现不影响其他层
便于维护 出问题可快速定位到具体层
复用性 一个 Service 可被多个 Controller（Web、API、定时任务）调用
利于协作 不同开发者可以并行开发不同层

六、与 MVC 的关系（易混淆点）

  • MVC 是表现层内部的设计模式：Model（数据）、View（页面）、Controller（控制器）。
  • 三层架构 是整个应用的架构分层思想。
  • 前后端分离项目中，View 由前端（Vue/React）负责，后端的三层架构中 MVC 主要体现在 Controller 层。

七、常见注解速查

注解 层 说明
@Controller 表现层 标识控制器，返回视图
@RestController 表现层 @Controller + @ResponseBody，返回 JSON
@Service 业务层 标识业务逻辑组件
@Repository 持久层 标识数据访问组件，会转换数据库异常
@Component 通用 无法归层的普通组件
@Mapper 持久层 MyBatis 接口扫描
@Transactional 业务层 声明式事务
