单元测试详解

一、什么是单元测试

单元测试（Unit Test）是对程序中最小可测试单元（通常是一个方法/类）进行的验证，目标是：隔离外部依赖，只验证当前单元自身的逻辑。

测试类型 测试对象 依赖处理 速度
单元测试 单个方法/类 Mock 掉所有外部依赖 毫秒级
集成测试 多个模块协作 真实数据库/中间件 秒级
端到端测试 整个系统 全真实环境 慢

为什么必须写单元测试

  1. 防止回归：改代码后一键验证没有破坏已有功能。
  2. 改善设计：难写测试的代码，往往就是耦合过重的代码（测试是最早的”代码评审员”）。
  3. 活文档：测试用例就是方法的用法示例。
  4. 放心重构：有测试兜底才敢大胆改代码。

常见误区：单元测试不是”main 方法里 print 一下看看”，而是断言自动化验证——通过绿灯，不通过红灯，不需要人眼判断。

三、Mockito：隔离外部依赖

1. 为什么需要 Mock

测试 UserService.registerUser() 时，它内部调用 UserDao.save() 写数据库——

  • 单元测试不应该真的连数据库（慢、脏数据、环境依赖）。
  • 解决：用 Mockito 造一个”假的” UserDao，指定它的返回值，并验证它被正确调用。

3. 常用打桩与验证

API 说明
when(mock.m(x)).thenReturn(v) 指定返回值
when(mock.m(x)).thenThrow(e) 指定抛异常
when(mock.m(x)).thenAnswer(inv -> ...) 自定义逻辑（如动态返回）
doReturn(v).when(mock).m(x) 同 thenReturn，适合 void 方法/ Spy
doNothing().when(mock).m(x) void 方法什么都不做（默认行为）
verify(mock, times(n)).m(x) 验证调用了 n 次
verify(mock, never()).m(x) 验证从未调用
verify(mock).m(argThat(x -> ...)) 用自定义规则验证参数

Mock 对象未打桩的方法默认返回 null / 0 / false / 空集合，不会执行真实逻辑。

3. 其他原则

  1. 一个测试只验证一件事，失败时立刻知道哪里错了。
  2. 不依赖执行顺序，每个测试独立、可重复、可并行。
  3. 不用 sleep，异步场景用 Awaitility 等工具等待条件。
  4. 测试代码也是代码——同样要整洁，重复的打桩逻辑抽成方法或 @BeforeEach。
  5. 优先测试边界：空输入、null、极大值、并发、异常路径，而不只是正常路径。
  6. 测试金字塔：单元测试多（70%+）、集成测试适量（20%）、端到端少（<10%）。

七、常见面试题速答

  1. 单元测试和集成测试区别？ 单元测试隔离依赖只测逻辑，快且稳定；集成测试验证模块协作，慢但更接近真实。
  2. Mock 和 Stub 的区别？ Stub 是”指定输入返回什么”（状态验证），Mock 还能”验证是否被调用过”（行为验证）。
  3. @Mock 和 @MockBean 区别？ 前者是纯 Mockito 注解，不起 Spring 容器；后者替换 Spring 容器中已存在的同类型 Bean，用于切片/集成测试。
  4. 如何测试私有方法？ 不直接测——通过公共方法间接覆盖；如果私有方法复杂到必须单测，说明应该抽取为独立类。
  5. @Transactional 在测试类的效果？ 测试方法结束后自动回滚数据库操作，保证测试数据不残留（注意：异步/新事务中的写入不受此回滚控制）。
