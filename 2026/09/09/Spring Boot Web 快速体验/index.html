六、核心知识点总结

6.1 为什么要继承 spring-boot-starter-parent？

继承该父 POM 的核心价值是简化配置、规避坑点：

  1. 版本统一管理：父 POM 预设了所有 Spring Boot 依赖的兼容版本，引入依赖时无需手动写版本号，避免版本冲突。
  2. 插件简化配置：内置 Spring Boot 常用 Maven 插件（如打包插件）的适配版本，无需重复配置。
  3. 基础配置预设：默认配置 UTF-8 编码、适配的 Java 版本等，省去基础配置工作。

简单说：父 POM 是 Spring Boot 官方的「配置模板」，让你聚焦业务而非基础配置。

6.2 为什么依赖叫“场景启动器”？有什么好处？

Spring Boot 的「场景启动器（Starter）」是一站式依赖解决方案，核心好处是「一键引入场景所需所有资源」：

  • 官方场景启动器命名：spring-boot-starter-*（如 spring-boot-starter-web）。
  • 第三方场景启动器命名：*-spring-boot-starter（如 mybatis-spring-boot-starter）。

导入对应场景启动器后，Spring Boot 会自动引入该场景的所有依赖、完成默认配置（如导入 web 启动器后，自动引入 Tomcat、Spring MVC 等并配置），实现「场景一导入，万物皆就绪」。

官方所有场景参考：https://docs.spring.io/spring-boot/docs/current/reference/html/using.html#using.build-systems.starters

6.3 为什么点击启动类就能运行整个项目？

核心就两个关键点：

  1. main 方法是程序入口：Java 程序启动入口就是 main 方法，点击启动类本质是执行这个方法。
  2. 注解 + run 方法完成初始化：
    • @SpringBootApplication：让 Spring 自动扫描并加载项目中的功能类（如 Controller）。
    • SpringApplication.run(...)：启动 Spring 核心容器，同时自动启动内置 Tomcat 服务器，加载所有配置和组件。

两者结合，只需运行启动类，就能完成「组件加载 + 服务器启动」，整个项目即可运行。

七、核心注解参考

注解 作用
@Controller 声明一个控制器组件（默认返回视图/页面）
@ResponseBody 声明响应体，数据以响应体方式返回（而非页面）
@RestController 声明控制器组件并纳入 IOC 容器管理；等价于 @Controller + @ResponseBody
@RequestMapping 声明路径映射，用于客户端访问（可作用于类或方法）
@SpringBootApplication 声明一个 Spring Boot 应用主程序（含自动配置与组件扫描）
@GetMapping 映射 GET 请求（查询）
@PostMapping 映射 POST 请求（新增）
@PutMapping 映射 PUT 请求（修改）
@DeleteMapping 映射 DELETE 请求（删除）

提示：@GetMapping / @PostMapping / @PutMapping / @DeleteMapping 是 @RequestMapping(method = ...) 的语义化简写，推荐在 REST 风格接口中直接使用，可读性更好。

八、本章小结

  1. Spring Boot 项目创建核心是选对场景启动器（如 web），继承父 POM 可大幅简化配置。
  2. 控制器类需放在主启动类的包 / 子包下，@RestController + @RequestMapping 可快速定义接口。
  3. 启动类的 main 方法 + @SpringBootApplication 是项目运行的核心，可自动完成容器和服务器启动。
  4. 常用请求映射可用 @GetMapping 等语义化注解替代宽泛的 @RequestMapping。
