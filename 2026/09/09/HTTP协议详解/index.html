HTTP 协议详解

1. HTTP 是什么

HTTP（HyperText Transfer Protocol） 即超文本传输协议，是应用层面向对象的协议，核心作用是规定客户端与服务器之间的通信规则。

简单说：浏览器和服务器之间对话，总得有个统一的语言——这个语言就是 HTTP。

HTTP 基于 TCP/IP 通信协议来传递数据（HTML 文件、图片、JSON 数据等）。

2. HTTP 版本演进

版本 核心特点 解决的问题
HTTP/1.1 持久连接（一个 TCP 传多个请求），但请求排队（队头阻塞） 避免反复建立连接
HTTP/2 二进制分帧，一个 TCP 并行传多个请求帧 解决队头阻塞
HTTP/3 基于 UDP 的 QUIC 协议，彻底解决 TCP 层阻塞 连接更快、抗网络波动

通俗理解：

  • HTTP/1.1 = 打电话，打完一个再打下一个（排队）
  • HTTP/2 = 打电话但可以多人同时说话（多车道）
  • HTTP/3 = 换成更快的网络线路（UDP QUIC）

6. 八种请求方法

方法 描述 数据位置 幂等 常见场景
GET 获取资源 URL（?后） ✅ 幂等 查询列表、查详情
POST 新增资源 请求体 ❌ 非幂等 注册、上传文件、登录
PUT 更新资源（全量） 请求体 ✅ 幂等 全量修改用户信息
DELETE 删除资源 URL（可选） ✅ 幂等 删除评论、删除用户
PATCH 部分更新 请求体 ❌ 非幂等 只改某个字段
HEAD 获取响应头 — ✅ 幂等 检查资源是否存在
OPTIONS 允许的方法 — ✅ 幂等 跨域预检
TRACE 回显请求 — ✅ 幂等 调试追踪

幂等：简单理解就是”发 1 次和发 100 次效果一样”，GET/PUT/DELETE 是幂等的，POST/PATCH 不是。

GET vs POST 最核心的区别：

对比 GET POST
数据在哪 URL 后 ?key=value 请求体里
数据可见性 地址栏可见，不安全 请求体里，相对安全
长度限制 浏览器通常限 2KB~8KB 无限制
能否收藏 ✅ 能（URL 确定） ❌ 不能
缓存 ✅ 有缓存 ❌ 无缓存

7. 常用请求头与响应头

常用请求头

请求头 说明 示例
Host 目标服务器域名+端口 Host: www.example.com
User-Agent 客户端类型（浏览器等） Mozilla/5.0 (Windows NT 10.0...)
Accept 告诉服务器客户端能接受什么 Accept: application/json
Content-Type 请求体数据格式 application/json、application/x-www-form-urlencoded
Content-Length 请求体字节长度 Content-Length: 234
Cookie 携带客户端 Cookie JSESSIONID=xxx
Authorization 认证信息（Token 等） Bearer eyJhbGci...

常用响应头

响应头 说明 示例
Content-Type 响应体数据类型 text/html; charset=UTF-8
Content-Length 响应体字节长度 Content-Length: 12345
Set-Cookie 让客户端种 Cookie JSESSIONID=xxx; Path=/
Cache-Control 缓存策略 Cache-Control: no-cache
Access-Control-Allow-Origin 跨域允许（解决 CORS） Access-Control-Allow-Origin: *

8. HTTP 状态码（重点）

状态码由三位数字组成，第一个数字决定了状态码的类型：

2xx 成功

状态码 含义 使用场景
200 OK 最常见，GET/POST 成功都返回这个
201 Created POST 新增资源成功（接口标准返回）
204 No Content 成功但没有响应体（如 DELETE 成功）

3xx 重定向

状态码 含义 使用场景
301 永久移动 域名换地址，浏览器会记住新地址
302 临时移动 临时跳转（如未登录跳转登录页，resp.sendRedirect()）
304 Not Modified 资源未修改，浏览器用缓存

4xx 客户端错误（前端/调用方常遇到）

状态码 含义 常见原因
400 Bad Request 请求参数格式错误、JSON 语法错、字段类型不对
401 Unauthorized 未登录、未提供 Token
403 Forbidden 已登录但没有权限
404 Not Found URL 路径写错、接口未部署、参数 id 不存在
405 Method Not Allowed 请求方法写错了（如接口只支持 POST，你用了 GET）
422 Unprocessable Entity 参数格式对了但语义有问题（如邮箱格式对但不存在）
429 Too Many Requests 请求太频繁，被限流了

5xx 服务器错误（服务端常遇到）

状态码 含义 常见原因
500 Internal Server Error 服务器代码抛异常（空指针、SQL 错等，最常见）
502 Bad Gateway 网关（如 Nginx）收到了上游服务器的错误响应
503 Service Unavailable 服务器过载、维护中、停了
504 Gateway Timeout 网关等上游服务器响应超时

10. GET 与 POST 实战场景对比

场景 选择 理由
用户登录 POST 密码放请求体里，比放 URL 更安全
用户注册 POST 新增资源，数据隐私不能放 URL
查询商品列表 GET 只读，参数放 URL 简洁
查询商品详情 GET 只读，用路径参数 /goods/123
修改用户昵称 PUT 更新已有资源，数据放请求体更安全
删除评论 DELETE 删除操作，幂等，用路径参数 /comment/456
上传图片 POST 大文件只能放请求体，URL 装不下
搜索商品 GET 纯查询，放 URL 可分享、可收藏
