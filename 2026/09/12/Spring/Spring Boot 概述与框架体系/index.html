Spring Boot 概述与框架体系

一、学习路线

Web 与框架的整体学习路线如下，Spring Boot 是第一步的「入口框架」：

Spring Boot → Spring MVC → MyBatis → MyBatis-Plus → Spring 高级 → Spring Boot 高级
  • Spring Boot：快速搭建 Java Web 项目脚手架，自动配置大部分框架。
  • Spring MVC：处理 Web 项目的「请求 - 响应」流程。
  • MyBatis：连接数据库的持久层框架。
  • MyBatis-Plus：MyBatis 的增强工具，提供通用 CRUD、分页等。
  • Spring 高级：深入 IOC/AOP、事务管理等底层原理。
  • Spring Boot 高级：自定义 Starter、分布式配置、性能优化等。

二、Web 核心概念

2.1 Web 项目定义

Web 项目是基于网络通信，由客户端和服务器组成的程序：

  • 客户端：一般用于「展示内容」和「数据收集」（如浏览器、App）。
  • 服务端：一般用于「业务逻辑处理」和「数据处理」（如部署在机房的服务器）。

核心特质：数据存放在远程服务端，跨设备可同步（如订单在手机 / 电脑都能看）。

2.2 客户端与服务器（C/S 与 B/S）

架构 说明 客户端示例 服务端
C/S（Client/Server） 需安装专用客户端，本地运行连接服务器；用户粘度高 手机 App、微信小程序、AI 智能体 Tomcat
B/S（Browser/Server） 浏览器即客户端，无需安装，网页访问即可用；方便快捷 PC 浏览器 Tomcat

两类架构的本质区别：客户端是否需要「安装」。B/S 是 C/S 在浏览器场景下的一种特例。

2.3 静态资源与动态资源

服务端返回给客户端的内容分为两类：

资源类型 包含内容 特点
静态资源 HTML、CSS、JS、图片、MP3、MP4 内容固定，谁看都一样（如首页 logo、按钮样式）
动态资源 由程序根据条件实时生成（替代过时的 Servlet/JSP） 内容随用户变化，如「你的个人订单列表」「按条件查库返回的数据」

2.4 HTTP 协议

2.4.1 简介

HTTP（HyperText Transfer Protocol，超文本传输协议）是应用层的面向对象协议，设计目的是确保客户端与服务器之间的通信，是互联网上最常用的协议之一。其核心包含两部分：通信规则 与 请求 / 响应报文。

2.4.2 通信流程

  1. 建立连接：客户端与服务器建立连接。传统 HTTP 基于 TCP/IP；HTTP/2 使用基于 TCP 的二进制协议，HTTP/3 使用基于 UDP 的 QUIC 协议。
  2. 发送请求：客户端发送请求，包含 URL、请求方法（GET/POST/PUT/DELETE 等）、请求头（Accept、User-Agent 等）以及可选的请求体（POST/PUT）。
  3. 处理请求：服务器根据请求找资源、执行业务（可能涉及查库、生成动态内容或返回静态文件）。
  4. 发送响应：服务器将结果封装为响应，包含状态码、响应头（Content-Type、Content-Length 等）以及可选的响应体（HTML、图片数据等）。
  5. 关闭连接：完成请求-响应周期后关闭连接，除非使用持久连接（如 HTTP/1.1 的 keep-alive）。

2.4.3 请求数据格式

请求行：   请求方法 [空格] URL [空格] 协议版本 [回车][换行]
请求头：   头部字段名 [:] 值 [回车][换行]
请求头：   头部字段名 [:] 值 [回车][换行]
...        （请求头可有多组）
空行：     [回车][换行]
请求体：   （客户端传递的数据，GET 请求通常无请求体）

2.4.4 响应数据格式

状态行：   协议版本 [空格] 状态码 [空格] 状态描述 [回车][换行]
响应头：   头部字段名 [:] 值 [回车][换行]
响应头：   头部字段名 [:] 值 [回车][换行]
...        （响应头可有多组）
空行：     [回车][换行]
响应体：   （服务器返回的数据）

2.4.5 常见请求方法

方法 语义 请求体 大小限制 幂等 说明
GET 查询 无 有（URL 传参，建议 ≤ 2KB） 是 数据放 URL 后，不安全
POST 新增 有 无 否 支持上传文件
PUT 修改 有 无 是 支持上传文件
DELETE 删除 无 有（URL 传参） 是 不安全

幂等：多次执行同一请求，对服务端资源产生的影响与执行一次相同（GET/PUT/DELETE 幂等，POST 不幂等）。

2.4.6 常见状态码

类别 含义 常见值
1xx 信息 —
2xx 成功 200 请求成功
3xx 重定向 302 重定向
4xx 客户端错误 400 参数错误；403 无权访问；404 资源未找到（多为路径错误）；405 请求方法不被允许
5xx 服务端错误 500 服务器异常；502 网关错误；503 服务不可用

2.5 服务器软件（运行容器）

服务端代码（如 Spring Boot 程序）需要「服务器软件」承载运行，核心作用是：接收 HTTP 请求 → 解析请求 → 运行代码 → 返回响应。常见软件：

  • Tomcat：Java Web 开发最常用，Spring Boot 内置即为此类。
  • Nginx：主要部署静态资源、做反向代理（提升稳定性）。
  • JBoss：企业级服务器，大型项目常用。

三、Spring 与 Spring Boot

3.1 Spring 简介

Spring 诞生于 2003 年，核心功能是：

  • IOC（控制反转）：对 Bean 的生命周期进行管理（对象不再由开发者手动 new，而是由容器创建与维护）。
  • AOP（面向切面编程）：将非业务代码（事务、日志、数据校验等）与业务代码分离，实现解耦。

通俗理解，Spring 好比 Java 程序员的「万能工具箱」+「智能管家」：包揽对象创建管理等杂活，并提供模块化工具（Web、数据库、安全等），让你专注写业务核心逻辑。

Spring 现已是一套技术栈全家桶，但其核心是 Spring Framework。

3.2 Spring Boot 简介

Spring Boot 诞生于 2013 年，是为了简化 Spring 开发而生的。主要好处：

  • 提供大量场景启动器（Starter），一键引入某场景所需依赖。
  • 内置 Tomcat 等服务器，直接用 java -jar 启动。
  • 简化配置，遵循「约定大于配置」。
  • 自带监控与健康检查。

总结：Spring Boot 让 Spring 开发「少折腾、快上手、零配置」，直接专注写业务代码。

后续文中「Spring」若无特殊说明，均指 Spring Framework。

3.3 框架关系与分层结构

从下到上是「基础 → 核心 → 工具 → 应用」的依赖关系：

  • 最底层：Java —— 体系「地基」，所有 Spring 技术都基于 Java 开发。
  • 第二层：Spring Framework —— 核心骨架，提供 IOC、AOP 等能力；Spring Boot 也基于它扩展。
  • 第三层：Spring Boot —— 把 Framework 能力包装成便捷工具，简化配置、快速整合上层框架。
  • 最上层：Spring 家族框架 + 第三方框架 + 自定义工具 —— 实际使用的框架（如 Spring MVC、MyBatis），靠 Spring Boot 简化整合。

依赖逻辑一句话：Java 打底 → Spring Framework 做核心 → Spring Boot 当简化工具 → 支撑我们用各种框架做开发。

3.4 为什么直接基于 Spring Boot 讲解框架技术？

因为 Spring Boot 是当前企业开发的主流「入口框架」：

  • 它把 Spring、Spring MVC 等核心技术做了「自动配置」，跳过复杂的手动配置，让你快速从「写代码实现功能」入手，降低学习门槛。
  • 企业实际项目几乎都用 Spring Boot 搭建，直接基于它学习更贴合真实开发场景。

四、核心要点小结

  1. Web 项目 = 客户端 + 服务端，通过 HTTP 协议交互，由服务器软件（Tomcat 等）承载运行。
  2. HTTP 协议关注报文格式（请求行/头/体、状态行/头/体）、请求方法语义与状态码含义。
  3. **Spring（2003）**以 IOC/AOP 为核心；**Spring Boot（2013）**在其之上做简化（自动配置、内置服务器、场景启动器）。
  4. 技术栈分层：Java → Spring Framework → Spring Boot → 上层框架，越下层越基础。
  5. 学习路径：以 Spring Boot 为入口，依次掌握 Spring MVC、MyBatis、MyBatis-Plus，再进阶 Spring / Spring Boot 高级。
