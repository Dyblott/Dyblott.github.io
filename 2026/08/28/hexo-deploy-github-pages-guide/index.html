Hexo 部署到 GitHub Pages 完整安装指南

适用对象：已安装 Hexo + NexT 主题，希望将博客部署到 GitHub Pages 的个人用户
最终访问地址：https://dyblott.github.io
文档更新：2026-08-28

0. 前置确认（先看）

检查项 你的现状 是否通过
GitHub 账号 有 dyblott 或新号 ☐
仓库名 必须为 dyblott.github.io（精确匹配） ☐
仓库可见性 必须 Public（私有仓免费版无法开 Pages） ☐
分支名 新仓库默认 main ☐
Node.js 已安装（建议 v18+） ☐
hexo-deployer-git 已装可跳过，否则需安装 ☐

⚠️ 关于 Gitee Pages：Gitee 免费版的 Pages 服务在 2024 年后已实质下线/隐藏入口，不再推荐。GitHub Pages 是 Hexo 官方推荐的静态托管方案，免费、稳定、2026 年仍在服务[citation:7][citation:10]。

1. 创建 GitHub 仓库

  1. 登录 github.com，进入 dyblott 账号。
  2. 点击右上角 + → New repository。
  3. 仓库名必须填：dyblott.github.io（你的用户名 + .github.io）[citation:9][citation:10]。
  4. Visibility 选 Public（私有仓库无法开启 Pages）[citation:10]。
  5. 其他保持默认，不要勾选 Add a README file（首次部署会由 Hexo 写入）。
  6. 点击 Create repository。

💡 如果你之前已用别的名字建过仓，先删除或重命名，再建这个精确命名的仓。

2. 修改 Hexo 配置（核心步骤）

打开本地博客项目根目录的 _config.yml，只改 deploy 和 URL 两段，其余不动。

2.1 URL 配置（必须与仓库配套）

这是方案 A（根路径部署）：静态文件直接放在仓库根目录，root: /。
不要写成 https://dyblott.github.io/blog，否则 CSS/JS 路径会 404。

2.2 Deployment 配置

参数说明[citation:2][citation:5]：

字段 说明 你的取值
type 部署方式 git
repo 目标仓库 HTTPS 地址 https://github.com/dyblott/dyblott.github.io.git
branch 推送到哪个分支 main（新仓库默认分支）
message 提交信息（可选，默认 Site updated: 时间） 不写则用默认

🔑 关于分支名：GitHub 新仓库默认分支已从 master 改为 main[citation:6][citation:12]。
hexo-deployer-git 对 GitHub 的默认值是 gh-pages，但用户页仓库发布的是默认分支，所以这里必须显式写成 main，否则推到不存在的 gh-pages 分支会失败[citation:2][citation:15]。

4. 本地生成 + 部署

首次部署会弹窗（正常现象）

hexo-deployer-git 通过 HTTPS 推送，第一次会要求输入 GitHub 用户名和密码[citation:2][citation:5]：

  • 用户名：你的 GitHub 账号（邮箱或用户名均可）
  • 密码：不是登录密码，是 Personal Access Token（PAT）

🔑 为什么要用 Token 而不是密码？
GitHub 已在 2021 年后禁用「账号密码」做 Git 认证，必须用 Token[citation:5][citation:14]。

生成 Token（只需一次）

  1. GitHub 右上角头像 → Settings → 左侧 Developer settings → Personal access tokens → Tokens (classic)。
  2. 点击 Generate new token → 勾选权限：repo（Full control of private repositories 那类，选 repo 即可）。
  3. 生成后立刻复制，只显示一次。
  4. 之后部署时把 Token 粘贴到密码框即可。

不想每次输入（可选，推荐）

用 SSH 方式免密推送，避免反复输入[citation:8]：

改完后重新 npx hexo deploy 即可免密。

5. 开启 GitHub Pages（自动发布）

hexo deploy 推完代码后，GitHub 会自动从默认分支构建网站，通常无需手动开 Pages。但为确保万无一失：

  1. 进入 dyblott.github.io 仓库 → Settings → 左侧 Pages。
  2. Build and deployment → Source 选择：Deploy from a branch。
  3. Branch 选 main，folder 选 /(root)。
  4. 点击 Save。

稍等 1~2 分钟，GitHub 会提示站点已就绪。

6. 验证访问

验证项 操作 预期结果
本地预览 npx hexo s → 打开 http://localhost:4000 样式正常、文章可读
线上访问 浏览器打开 https://dyblott.github.io 首页加载、CSS/JS 无 404
资源检查 浏览器 F12 → Network 所有 .css/.js/图片返回 200

🔍 样式全丢/白屏的常见原因：root 没配成对，导致资源路径 404。按本文 root: / 配置即可避免。

7. 日常使用（以后怎么发文章）

以后每次写完好文章，执行最后一条命令，推送即上线，无需登录 GitHub 任何页面。

8. 常见问题排查

报错 “Authentication failed / 401”

  • 用了账号密码登录 → 改用 Personal Access Token（见第 4 节）[citation:5]。
  • 检查 repo 地址是否拼错用户/仓库名。

页面能打开但样式丢失（无 CSS）

  • 检查 _config.yml 的 url 和 root 是否配套，root 必须是 /[citation:12]。
  • 检查浏览器 Network 里 CSS 是否 404。

分支选错 / 站点不更新

  • 确认仓库默认分支是 main，且 _config.yml 的 branch: main 与之一致[citation:12]。
  • 老教程写 master 的，在新仓库上会不生效。

私有仓库想开 Pages

  • 免费档不支持私有仓开 Pages，需升级到 GitHub Pro（$4/月）[citation:7]。
  • 个人博客用公开仓即可，无需升级。

国内访问慢

  • GitHub Pages 国内偶有延迟，属正常现象。
  • 后期可绑自定义域名 + Cloudflare 代理提速，或迁移到 Cloudflare Pages。

附：仓库分工建议（可选，长期优化）

当前你把 Hexo 源码和 public/ 静态文件混在一个仓里。长期建议双仓分离[citation:9]：

仓库 用途 谁推送
dyblott.github.io 仅存 public/ 静态文件（Pages 源） hexo deploy 自动推
blog-src（或 dyblott/blog） 存 Hexo 源码（配置、主题、文章 md） 你本地 git push 手动推，做备份

这样源码修改不会污染部署仓，也方便换电脑/换环境时只克隆源码仓。
