抽象类及接口

抽象类

介绍

抽象类是一种”只能被继承、不能直接实例化”的类，它存在的意义是给子类定一份”必须实现的合同”——规定子类必须有哪些方法，但不关心这些方法具体怎么干。

抽象类（abstract class）是用 abstract 关键字修饰的类，它介于普通类和接口之间：既能定义必须由子类实现的方法规范，又能提供可被继承的成员变量和普通方法实现。核心价值是把”是什么”和”怎么做”分离——父类定契约、子类填细节

规则 说明
不能实例化 new Animal() 编译报错；只能 new Dog()，但可以用 Animal a = new Dog() 向上转型
抽象方法无方法体 以 ; 结尾，不能写 {}
有抽象方法的类必须是抽象类 反之不成立——抽象类可以没有抽象方法
子类必须实现全部抽象方法 否则子类也得声明为 abstract
abstract 不能与 final、static、private 共存 final 禁止继承、static 属于类、private 无法被子类访问，都与”要被子类重写”矛盾

注意事项

  • 抽象类不能直接new对象,只能创建非抽象子类的对象
  • 抽象类中,可以有构造方法,是供子类创建对象时,初始化父类中属性使用的
  • 抽象类中可以有成员变量,构造,成员方法
  • 抽象类中不一定非得有抽象方法,但是有抽象方法的类一定是抽象类
  • 抽象类的子类,必须重写父类中的所有抽象方法,否则,编译无法通过.除非该子类也是抽象类

接口

介绍

接口（interface）是 Java 中纯粹的行为契约：它只规定”能做什么”，完全不关心”是谁”。上一轮我们说过抽象类强调 is-a（是什么），而接口强调 can-do（能做什么）——它让毫无血缘关系的类，也能拥有同一种能力。

  • 接口:是一种标准,规范

  • 接口定义:interface
