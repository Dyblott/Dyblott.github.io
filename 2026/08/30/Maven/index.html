Maven 是什么

一句话：Maven 是 Java 项目的「项目构建」与「依赖管理」工具。

  • 构建：把写好的代码变成可运行的产物，自动化完成 清理 → 编译 → 测试 → 报告 → 打包 → 安装 → 部署。
  • 依赖管理：用坐标（GAV）声明项目需要的第三方库，Maven 自动从仓库下载、管理版本与传递依赖。

⚠️ Maven 命令必须在 pom.xml 所在目录 下执行。

好处：

  • 约定优于配置，目录结构统一，新人上手快；
  • 一条命令完成编译、测试、打包、发布，提升效率与交付质量；
  • 依赖自动下载与版本统一管理，告别手动拷贝 jar 包。

官方下载：https://maven.apache.org/

依赖信息查询：Maven Repository 或 IDEA MavenSearch 插件

二、项目约定结构（目录布局）

Maven 提倡「约定优于配置」，标准 Java 项目结构如下：

  • pom.xml：项目核心配置文件，描述依赖与构建信息
  • src/main/java：Java 源代码（标准 MVC 架构代码）
  • src/main/resources：资源目录（配置文件、静态资源等）
  • src/test/java：测试代码目录
  • src/test/resources：测试资源目录

三、POM 核心配置

pom.xml（Project Object Model）是 Maven 项目的核心描述文件。

1. 坐标（GAVP）

Maven 用 GAVP 四个属性给项目做「唯一身份标识」，让项目在仓库中可被精准找到，方便项目间相互引用。

属性 核心作用 是否必填
groupId 标识归属（公司/团队/业务线） 是
artifactId 标识具体项目/模块 是
version 标识迭代版本 是
packaging 标识打包类型（pom/jar/war） 否（默认 jar）

GAV 组合是项目的唯一标识，P 决定项目类型与打包结果。

命名规则明细：

  • groupId：格式 com.公司.业务线.[子业务线]（最多 4 级）
    • 示例：com.alibaba.sourcing（阿里 + 采购业务）
  • artifactId：格式 产品线名-模块名，语义唯一
    • 示例：tc-client（tc 产品线 - 客户端模块）
  • version：三段式 主版本号.次版本号.修订号
    • 主版本号：不兼容的 API 修改（1.0.0 → 2.0.0）
    • 次版本号：兼容的功能新增（1.0.0 → 1.1.0）
    • 修订号：仅修复 bug / 优化（1.0.0 → 1.0.1）
    • SNAPSHOT 表示开发中的快照版本

2. 打包类型 packaging

类型 说明 典型场景
pom 聚合/父工程，用于多模块项目与依赖管理，不生成打包文件 微服务多模块
jar（默认） Java 普通包 工具类、公共模块、Spring Boot
war Web 应用包 传统 Web 项目、部署到 Tomcat

四、生命周期与常用命令

Maven 有三套相互独立的生命周期：clean（清理）、default（核心构建）、site（生成站点）。日常最常用的是 default。

三套生命周期

生命周期 作用 包含命令
clean 清理编译产物，删除 target clean
default 核心构建周期，最常用 compile → test → package → install / deploy
site 生成项目站点报告 site

default 生命周期主要阶段

阶段 含义 对应命令
clean 删除 target 目录 mvn clean
compile 编译主代码 mvn compile
test 执行单元测试（自动生成测试报告） mvn test
package 打成 jar / war mvn package
install 安装到本地仓库 mvn install
deploy 发布到远程仓库 mvn deploy

执行某个阶段时，Maven 会 按顺序先执行它之前的所有阶段。例如 mvn package 会依次执行 resources → compile → testResources → testCompile → test → package。

常用组合命令

  • mvn clean package：清理后重新打包
  • mvn clean install：清理后编译、测试、打包并安装到本地仓库
  • mvn -DskipTests package：打包但跳过测试

插件、命令、生命周期的关系

  • 生命周期是一组固定构建命令的有序集合，触发后面的命令会自动触发前面的命令
  • 真正干活的是插件，命令只是触发插件的入口
  • 使用生命周期命令可以简化构建过程（如一条 mvn clean package 完成多步）

五、依赖管理（重点）

1. 依赖范围 scope

控制依赖在哪些阶段生效：

scope 编译(main) 测试(test) 运行 打包 典型例子
compile（默认） ✅ ✅ ✅ ✅ 大部分依赖
provided ✅ ✅ ❌ ❌ Servlet API（容器已提供）
runtime ❌ ✅ ✅ ✅ MySQL 驱动
test ❌ ✅ ❌ ❌ JUnit

2. 依赖传递

Maven 会自动把「依赖的依赖」也加入 classpath。例如 A 依赖 B，B 依赖 C，则 A 间接依赖 C，执行项目 A 时会自动把 B、C 都下载引入。

传递规则： C 能否传递到 A，取决于 B 依赖 C 时使用的 scope：

  • B 依赖 C 使用 compile：可以传递 ✅
  • B 依赖 C 使用 test 或 provided：不能传递 ❌

传递终止条件：

  • 非 compile 范围依赖不参与传递
  • 依赖冲突（传递的依赖已存在其他版本）会导致传递终止

4. 依赖下载失败排查

常见原因与解决方案：

原因 表现 解决方案
网络故障 / 仓库服务器异常 Remote host terminated the handshake 检查网络连接与仓库服务器状态
依赖版本号 / 坐标错误 Could not find artifact ... 确认依赖版本与 pom.xml 配置正确
本地缓存损坏（.lastUpdated 文件） 刷新无效，不重新下载 删除本地仓库对应目录下的 .lastUpdated 文件后刷新

⚠️ .lastUpdated 文件是 Maven 下载失败后的缓存标记，只要存在该文件，即使刷新也不会重新下载。需根据依赖的 GAV 逐级定位到对应目录，删除相关文件后再刷新。

六、继承与聚合

1. 继承关系

概念： 让子项目从父项目中继承配置信息，多个模块共享同一份配置，简化管理与维护。

作用：

  • 统一版本管理：父工程集中管理依赖版本，子模块复用，避免版本不一致

区别： <dependencies> 中的依赖会被真正引入且子模块自动继承；<dependencyManagement> 只管版本，子模块需要显式声明才引入。

2. 聚合关系

概念： 将多个子项目组织到一个父级项目中，以便一起构建和管理。

作用：

  • 一条命令构建和发布多个相关项目
  • 自动优化构建顺序，避免依赖混乱导致构建失败
  • 统一管理公共依赖与插件

语法：

在父工程目录执行 mvn clean package，Maven 会自动构建所有子模块（产生反应堆），按依赖顺序依次编译打包。

七、Maven 仓库体系

Maven 仓库分为三类，查找优先级从高到低：

仓库类型 说明 优先级
本地仓库 本地磁盘目录（默认 ~/.m2/repository），存放已下载的依赖 1️⃣ 最高
远程仓库 团队/公司私服或镜像仓库（如阿里云），作为中央仓库的加速替代 2️⃣
中央仓库 Maven 官方维护的公共仓库，包含大量开源构件 3️⃣ 最低

查找流程：

  1. Maven 需要某个依赖时，先查本地仓库 → 有则直接使用
  2. 本地没有 → 查远程仓库（如配置了镜像）→ 下载并缓存到本地
  3. 远程没有 → 查中央仓库 → 下载并缓存到本地

核心原则：本地仓库 > 远程仓库 > 中央仓库，只要本地已存在就不会再访问远程。

八、常用插件

Maven 的功能由插件（plugin）提供，每个构建阶段都绑定了默认插件。常用插件一览：

插件 作用
maven-clean-plugin 清理 target
maven-compiler-plugin 编译
maven-resources-plugin 处理资源文件
maven-surefire-plugin 执行单元测试
maven-jar-plugin 打 jar 包
maven-war-plugin 打 war 包
maven-install-plugin 安装到本地仓库
maven-deploy-plugin 部署到远程仓库
maven-site-plugin 生成项目站点
maven-source-plugin 打包源码
maven-javadoc-plugin 生成 JavaDoc
maven-shade-plugin 打包可执行 fat-jar（含依赖）
maven-assembly-plugin 自定义打包（zip/tar 等）
maven-dependency-plugin 依赖分析、拷贝

依赖 vs 插件：依赖是项目运行所需的第三方库（<dependencies>），插件是扩展构建过程的工具（<build><plugins>）。
